# Backend API contract

FastAPI publishes the current schema at `/openapi.json` and interactive documentation at `/docs`. Business routes are versioned under `/api/v1`; the checked-in snapshot is [services/api/openapi.json](../services/api/openapi.json). The API supports historical research, internal PAPER execution and separately gated Delta India DEMO controls. Production order submission remains unavailable.

## Authentication and security

`POST /auth/login` accepts username/password and, for enrolled users, a TOTP or recovery code. It sets an HttpOnly session cookie and returns the role and CSRF token. `GET /auth/me` returns the authenticated principal and CSRF token. `POST /auth/logout` requires the session, allowed origin and `X-CSRF-Token`, and invalidates the persisted session. Login and sensitive authentication attempts are throttled.

Business mutations require the operator role, allowed origin and CSRF token. Personal password, MFA and session actions use the authenticated user's identity with CSRF protection. Viewer accounts cannot execute trading or account administration actions. The Next.js server proxy forwards cookie/CSRF context; no exchange secret is embedded in browser bundles.

`/security` adds TOTP enrollment/confirmation, recovery codes, password changes, session discovery/revocation, operator/viewer administration and exact-version readiness evidence. Recent password authentication expires after five minutes. Sensitive account administration and DEMO activation/entry actions also require enabled MFA and a recently verified second factor. MFA enrollment requires an initialized local encrypted vault. Provisioning secrets and new recovery codes are deliberately returned only during their authenticated setup flow; they must not be logged.

Exchange credentials are configured through secure environment variables or the interactive local vault CLI. HTTP handlers do not accept or return exchange credential values. Vault status exposes credential names, generations and timestamps only. Readiness evidence does not enable live execution.

## Endpoint groups

All paths below are relative to `/api/v1`. OpenAPI supplies exact request fields, response schemas and supported methods.

| Group | Representative routes | Behavior |
| --- | --- | --- |
| Dashboard | `GET /dashboard` | Persisted PAPER account, positions, orders, equity, worker and data-age state. |
| Strategies | `GET/POST /strategies`, `GET/PUT /strategies/{id}`, `GET /strategies/{id}/versions` | Typed deterministic configuration; edits create an immutable version and invalidate approval. Advanced indicators, higher timeframes, regimes, filters, execution/protection and strategy risk policies are configurable. |
| PAPER lifecycle | `POST /strategies/{id}/validate`, `/backtest`, `/start`, `/pause`, `/stop` | Start requires current-version evidence, account/risk gates and exclusive symbol ownership. Pause/stop retains open positions and protection. |
| Backtests | `GET/POST /backtests`, `GET /backtests/{id}` | Stored version, pinned historical dataset identity, economics, costs, simulated fills and metrics. |
| Quantitative validation | `GET/POST /research/runs`, `GET /research/runs/{id}` | Bounded out-of-sample, walk-forward, stability, cost stress, Monte Carlo, benchmark, regime and portfolio reports, retaining evidence and reproducibility identities. Portfolio simulations require explicit strategy selections and capital allocation. |
| Research documents | `GET/POST /research/documents`, `GET /research/documents/{id}`, `GET/PATCH /research/candidates/{id}`, `POST /research/candidates/{id}/approve` | Resource-bounded text/Markdown/PDF extraction, source quotations and ambiguity review. Approval validates an explicit operator-supplied configuration; extracted prose never starts trading automatically. |
| PAPER account | `GET/POST /paper/account`, `POST /paper/account/reset`, `GET /paper/account/history` | Durable virtual account and movement/equity history. Reset requires confirmation, reconciled state, stopped strategies and no open positions or pending entries; history is retained. |
| PAPER execution | `GET /paper/execution`, `POST /paper/orders/{id}/cancel`, `GET/POST /paper/funding` | Pending entry reservations/cancellation and attributed funding schedules. Optional limit/partial-fill, protection and isolated liquidation assumptions are disclosed. Late funding observations require a quantity-at-time reconciliation workflow. |
| PAPER orders/fills/positions | `GET /orders`, `/fills`, `/positions`; `POST /positions/{id}/close` | Internal simulator ledger and fresh-data closure. PAPER never submits orders to either exchange environment. |
| PAPER risk/emergency | `GET/PUT /risk`, `POST /emergency-stop` | Audited risk settings and `BLOCK_ENTRIES`; separate confirmation for `RESUME_ENTRIES` or `FLATTEN_MANAGED`. Exposure changes require current risk/reconciliation evidence. |
| Instruments/history | `GET /instruments`, `POST /instruments/refresh`, `GET /market/candles`, `POST /market/import` | Read-only India public product/history ingestion. Invalid or missing observations do not become fabricated market records. |
| Historical datasets | `GET/POST /market/datasets`, `GET /market/datasets/{id}`, `/market/datasets/{id}/candles`, `/market/gaps`, `/market/revisions` | Immutable content hashes, pinned candle observations, completeness/warnings, missing intervals and observed revisions. |
| Public market feeds | `GET /market/feeds`, `/market/snapshot`, `/market/stream` | Central public ticker, book, trade, funding and provisional candle observations with health/source timestamps. Historical strategy candles still require validated closed REST observations; raw funding units are not certified for accounting. |
| DEMO account/products | `GET /demo/status`, `/demo/products`, `/demo/risk`; `POST /demo/connect`, `/demo/products/refresh`, `/demo/products/{id}/verify`, `/demo/reconcile`; `PUT /demo/risk` | Separate demo product IDs, reviewed contract economics and authenticated reconciliation. Missing credentials leave the integration blocked. |
| DEMO execution | `POST /demo/enable`, `/demo/disable`, `/demo/orders`, `/demo/orders/{id}/cancel`, `/demo/positions/{product_id}/close`; `GET /demo/orders`, `/demo/positions`, `/demo/fills`, `/demo/events`, `/demo/cash-movements` | Durable intents and exchange-specific state. New entries require explicit local demo authorization, recent MFA, verified economics, fresh reconciliation and healthy private stream/worker. UNKNOWN cannot be blindly resubmitted; disable blocks entries while retaining protection. |
| DEMO strategies | `GET /demo/strategies`, `POST /demo/strategies/{id}/start`, `/demo/strategies/{id}/pause` | Explicitly confirmed, exact-version runner approval with current validation/backtest and demo account/product gates. Starting a runner does not certify actual exchange acceptance. |
| News/events | `GET/POST /news/sources`, `PUT /news/sources/{id}`, `GET/POST /news/events`, `/news/blackouts`, `PUT /news/blackouts/{id}`, `GET /news/entry-check` | Timestamped public/source-attributed observations, explicit blackout policies and conservative entry checks. Required stale/missing sources fail closed. |
| Reports/analytics | `GET/POST /reports`, `GET /reports/analytics`, `/reports/{id}`, `/reports/{id}/export` | Stored PAPER daily/weekly/monthly reports, observed execution/regime/portfolio analytics and JSON/CSV export. Completed-period schedules use Asia/Calcutta boundaries and report missing historical evidence. |
| Notifications/Telegram | `GET /notifications`, `POST /notifications/{id}/read`; `GET/PUT /integrations/telegram`, `GET /integrations/telegram/outbox`, `POST /integrations/telegram/outbox/{id}` | Durable in-app events and a retryable Telegram outbox. Delivery requires configured token, chat/user allowlists and explicit delivery enablement. Remote commands are read-only; delivery status distinguishes offline tests from actual delivery. |
| Security/readiness | `/security/status`, `/security/reauth`, `/security/mfa/*`, `/security/sessions`, `/security/users`, `/security/readiness/{id}` and its `/evidence` route | Personal/admin security flows and exact-version PASS/FAIL/PENDING readiness evidence. Protection of the last active operator and session invalidation accompany relevant changes. |
| Settings/observability | `GET/PUT /settings`, `GET /integrations`, `/live-readiness`, `/system-health`, `/worker/health`, `/monitoring` | Planning inputs, integration metadata, observed worker/feed/reconciliation/backup health and explicit missing live gates. |
| Dashboard streaming | `GET /events` | Authenticated periodic complete snapshots; streams recheck active sessions. Reconnect and REST recovery remain necessary. |

Public service probes use `/health`, `/ready` and the startup alias `/health/ready`. `/metrics` is outside `/api/v1` and provides Prometheus telemetry for observed HTTP, workers, feeds, reconciliation, orders and backups. Generic service readiness does not authorize trading. Follow [development.md](development.md) for local startup and [operations.md](operations.md) for monitoring/deployment boundaries.

`GET /signals` and `GET /risk/decisions` expose bounded PAPER signal and entry-decision evidence, optionally filtered by strategy. Decisions retain actual checked limits, context, requested/sized/approved quantity and rejection reasons; unavailable earlier estimates are not invented. `GET /clock` exposes the bounded public HTTPS time observation, freshness, uncertainty and blocking reasons. This estimate does not certify exchange signing time or replace NTP.

`GET/POST /demo/reports`, its detail and JSON/CSV export routes persist independent native-currency DEMO daily/weekly/monthly evidence. They never reuse a PAPER account or infer currency conversion. Unsupported DEMO strategy policies are rejected explicitly; see [the capability boundary](demo-trading.md).

## Errors and evidence boundaries

Input shape/limits produce validation errors; authentication/authorization failures return `401`/`403`, absent records `404`, gate/state conflicts `409`, oversized research documents `413`, throttling `429`, and unavailable exchange operations `503`. Validation and transport failures suppress sensitive input values and raw credential-bearing responses.

Many list routes deliberately expose bounded recent history rather than unbounded queries. Report export is supported; general pagination and arbitrary export should be assessed per route. Actual credentialed DEMO authentication/private stream/order scenarios and Telegram delivery require their external configuration and separate evidence. Offline fault/contract tests do not establish private exchange acceptance or VPS readiness. Production execution remains structurally disabled. Current executed checks and outstanding external work are recorded in [PROGRESS.md](../PROGRESS.md).
