# Research, events, reports and Telegram

Research imports store bounded text/Markdown or text-bearing PDFs with the operator, source reference and SHA-256 content identity. PDF parsing runs in a separate process with 256 MiB memory, eight CPU seconds, a twelve-second deadline, one hundred pages and 250,000 extracted characters. Encrypted and image-only books require separately extracted text. The deterministic extractor identifies sections and quotes entry, exit, indicator and risk passages. It labels subjective or missing conditions as ambiguities; it does not invent executable rules or claim confidence from a language model.

The operator edits the structured specification, explicitly resolves `automation_ambiguities`, and confirms a syntactically valid deterministic `StrategyConfig`. Approval preserves the source record and creates an immutable **DRAFT** strategy version. Normal strategy validation, historical backtesting and execution eligibility still apply. Research approval never starts trading. Approved research records cannot be edited. Import a revised source to retain a new attributed review history.

Event sources require explicit operator authorization. Manual event import includes an external ID, category, impact, publication timestamp, optional scheduled timestamp, affected symbols and a source reference. Both timestamps require timezones; future publication times and unrecognized schemas are rejected. Event identity deduplicates unchanged source/external-ID payloads. Corrections append a new revision and mark the prior revision superseded at the new receipt time. Reversions also preserve every intervening revision. Equivalent stories retain each publisher’s attribution and do not create duplicate alerts. No sources or events are seeded into the application. The optional HTTPS JSON feed adapter polls only configured source URLs whose public host appears in `NEWS_ALLOWED_HOSTS`. It prohibits credentials in URLs, custom ports, private address resolutions and redirects, limits response size and event count, validates all events before import, and records generic polling failures.

Blackout rules define categories, minimum impact, affected symbols and minutes before/after an event. The execution gate checks the revision that was published, received and not yet superseded at the decision timestamp. Future-known historical events cannot influence a prior decision. A source marked required for trading also blocks new entries when it has never refreshed or becomes stale. Disabling a rule removes its entry block. Protection and exits continue during entry blackouts. Source attribution establishes provenance; it does not guarantee the publisher's facts.

Reports use persisted PAPER fills, closed positions, account snapshots, incidents and funding/capital movement records. Daily, weekly and monthly boundaries use Asia/Calcutta; weekly periods begin Monday. Automatic scheduling creates only completed periods after the account existed. Reports are immutable and idempotent by account, mode and interval. CSV and JSON exports include their mode and reporting currency. Current rolling analytics are available separately.

Version 2 reports include fill fees, recorded liquidation fees and recorded funding; account reset capital flows are removed from equity return and snapshot drawdown so deposits and withdrawals do not appear as trading profits or losses. A funding result covers only recorded simulated funding movements, not an inferred exchange history. Missing opening/closing snapshots remain null with coverage warnings. Historical capital allocation reconstructs quantities from persisted fills, then applies the immutable contract and exact strategy version to the last closed mark candle; incomplete position evidence is listed explicitly. Execution quality compares stored first-fill prices with independent entry references and reports its coverage; later partial fills and exchange latency are not inferred. Regime performance uses stored entry regime tags and counts unattributed trades. Snapshot drawdown scans all stored samples while exported equity curves retain a bounded selection; it cannot measure unsampled intrabar losses. CSV text cells are escaped against spreadsheet formula interpretation.

Telegram stores configuration metadata and a durable outbox, never the bot token. Set `TELEGRAM_BOT_TOKEN` through a server secret manager or protected environment, enable `TELEGRAM_DELIVERY_ENABLED=true`, and save both numeric chat and sender-user allowlists before permitting transport. `/status`, `/balance`, `/positions`, `/orders`, `/strategies`, `/pnl`, `/risk`, `/health` and `/logs` return bounded read-only summaries. Every inbound command requires both IDs to match. Unknown commands and remote trading commands create no execution actions. Tokens and provider response bodies are excluded from saved errors.

Notification rendering preserves the source message and never assigns PAPER scope to DEMO or shared alerts. Existing notification records have no structured execution mode, so their wrapper says `MODE UNSPECIFIED`; mode words in prose do not become metadata. Read-only account commands remain explicitly PAPER scoped. Notifications enter an idempotent outbox; delivery attempts are committed before network calls, use bounded exponential retry, honor rate-limit delays and stop after eight attempts. Operators can retry or cancel undelivered entries. A worker crash or ambiguous timeout can duplicate an alert because Telegram has no client-message idempotency key. Notification and polling failures occur outside critical trading recovery transactions. Transport remains disabled by default; actual Telegram delivery requires credentials and has **not** been verified in this environment. Offline tests use mocked HTTP transports and never send messages.

API routers: `/api/v1/research`, `/api/v1/news`, `/api/v1/reports`, and `/api/v1/integrations/telegram`. News lists show current revisions by default; `?include_history=true` or `/news/events/{id}/history` exposes their preserved history. Read endpoints require a session; changes require the operator role, same-origin checks and CSRF.
