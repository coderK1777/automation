# Known limitations and remaining acceptance

The implemented research/PAPER platform and gated DEMO backend are distinct from completed exchange and deployment acceptance. [PROGRESS.md](../PROGRESS.md) records actual results; [requirements.md](requirements.md) retains the full target. Live routing is structurally unavailable.

- **Private exchange acceptance:** No usable raw demo signing credentials are configured. Actual authentication, order/cancel/fill/protection, private-stream recovery, cash reconciliation and current exchange error/rate-limit behavior remain unverified. Offline contracts and PostgreSQL locks do not establish exchange acceptance. Minimums and margin tiers need current official evidence before DEMO approval.
- **DEMO scope and lifecycle:** The executor supports the subset documented in [DEMO](demo-trading.md). It explicitly rejects unsupported advanced entry/exit policies, strategy caps, news/funding filters and correlated groups; these need further implementation and exchange acceptance. An attached protective exit observed before its parent relationship is established remains unowned and blocks reconciliation. Automatic trailing-order replacement remains disabled. Unknown submissions retain reservations and never authorize a second POST.
- **Simulation:** Closed OHLC cannot establish intrabar paths, queue priority or real liquidity. LIMIT/partial fills use declared penetration/volume assumptions. Gaps can defeat calculated break-even. Liquidation uses an explicitly configured isolated linear model, not Delta cross-margin logic. Funding is supplied/attributed, never invented from unverified feed units. See [quantitative core](quantitative-core.md) and [persisted PAPER execution](persisted-paper-execution.md).
- **Research:** Bounded PDF parsing supports text-bearing documents; scanned/encrypted books need extracted text. Subjective passages require operator resolution. Portfolio research uses synchronized isolated capital sleeves, not exchange netting/shared collateral/execution competition. Historical news availability begins with recorded observations; unavailable required evidence fails closed.
- **Data provenance:** WebSocket candle timestamps do not certify candle-open identity, so authoritative REST observations supply closed history. Feed funding retains raw units until certified for accounting. Missing/gapped datasets and stale required feeds block affected workflows.
- **Reports:** Returns remove recorded capital resets and include recorded fees/funding. Missing allocation, benchmarks, regime evidence or snapshots produce explicit coverage warnings/nulls. Snapshot drawdown cannot measure unsampled intrabar losses.
- **Telegram:** Durable outbox, retries and allowlisted read-only commands are implemented. No token or authorized chat/user configuration is present, so delivery is unverified. Ambiguous timeouts can duplicate an alert because Telegram has no client idempotency key.
- **Deployment/recovery:** Local containers, encryption and disposable restore checks do not establish a deployed VPS, public HTTPS, host reboot recovery, sustained alert delivery or off-host disaster recovery. A domain/contact, verified backup destination and separately protected recovery key remain to be provisioned. Normal startup makes no offsite transfer.
- **Security and release:** MFA, roles, session administration and encrypted credentials are implemented. Independent security/risk/operations review and production threat assessment remain external gates. Saving cloud configuration does not publish it. Fresh-task startup remains unverified. The original checkout was empty/unborn; GitHub transfer is a separately authorized source-publication step and does not deploy the application.
- **Production execution:** A production private executor is not implemented. Readiness records and a disabled live dashboard do not satisfy the full live-execution requirement. That work remains a separately reviewed phase after DEMO acceptance and operational review; no local test authorizes production orders.

An endpoint, disabled UI control or offline fixture does not prove its external acceptance gate passed. Live activation never follows automatically from a profitable backtest.
